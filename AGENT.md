# Processus obligatoire avant de créer un site

Identifier :

- service principal;
- services secondaires;
- zone réellement desservie;
- client cible;
- problème urgent;
- bénéfice principal;

Avant de choisir les pages à créer :

1. rechercher les requêtes actuelles;
2. analyser les résultats Google;
3. identifier l'intention dominante;
4. analyser les pages concurrentes qui occupent les meilleures positions;
5. repérer leurs forces, faiblesses et angles manquants;
6. regrouper les mots-clés par **intention**, pas simplement par similarité;
7. identifier les requêtes transactionnelles prioritaires;
8. identifier les questions secondaires utiles;
9. identifier les opportunités locales;
10. identifier les contenus qui peuvent soutenir les pages commerciales.

Prioriser notamment :

- soumission + service;
- service + ville;
- entrepreneur + service;
- prix + service;
- coût + service;
- installation + service;
- réparation + service;
- urgence + service;
- subvention + service;

# Architecture SEO

Créer une architecture simple et logique.

Exemple :

- `/` — page principale / page pilier;
- `/isolation/` — service principal;
- `/isolation-entretoit/` — sous-service;
- `/isolation-sous-sol/`;
- `/prix-isolation/`;
- `/subventions-isolation/`;
- `/regions/laurentides/`;
- `/isolation/saint-jerome/`;
- `/isolation/laval/`;
- `/guides/...` — contenus informatifs utiles.

## Règle essentielle sur les pages locales

**Ne jamais créer des dizaines ou centaines de pages quasi identiques où seul le nom de la ville change.**

Une page locale doit mériter d'exister.

Elle doit idéalement inclure plusieurs éléments réellement distincts :

- contexte de la ville/région;
- types de propriétés fréquents;
- problèmes typiques;
- climat / saisonnalité lorsque pertinent;
- zones voisines;
- disponibilité réelle;
- données locales vérifiées;
- programmes ou règles applicables;
- exemples de projets réels lorsque fournis;
- FAQ locale;
- photos locales ou projets locaux lorsque disponibles;
- témoignages authentiques de cette zone;
- liens internes adaptés.

Si la valeur locale est insuffisante, créer une page régionale plus forte plutôt qu'une page faible.

# Copywriting Senior — méthode LL MEDIA

Le copywriting doit être écrit pour une personne qui cherche une solution maintenant.

## Hero

Le visiteur doit comprendre en moins de 3 secondes :

1. ce qu'on lui propose;
2. pour quel problème;
3. dans quelle région;
4. pourquoi il devrait remplir le formulaire.

### Structure recommandée

**Eyebrow** : catégorie / zone / preuve.

**H1** : service + bénéfice principal.

**Sous-titre** : résultat + différenciation + réduction du risque.

**Preuves** : 2 à 4 preuves concrètes.

**CTA** : un seul objectif principal.

## Principes de rédaction

Écrire :

- court;
- spécifique;
- concret;
- crédible;
- conversationnel;
- québécois naturel;
- orienté bénéfices;
- sans jargon inutile.

Préférer :

- « Comparez des soumissions d'entrepreneurs vérifiés »
à
- « Nous sommes une solution innovante de mise en relation ».

Préférer :

- « Obtenir mes soumissions »
à
- « Soumettre ».

## Angles de conversion

Selon le service, tester :

- économiser;
- éviter une erreur coûteuse;
- comparer les prix;
- obtenir une estimation;
- urgence;
- confort;
- sécurité;
- garantie;
- subvention;
- disponibilité limitée réelle;
- entrepreneur vérifié;
- simplicité;
- gain de temps;
- protection de la propriété.

## Objections à traiter

Répondre naturellement à :

- Combien ça coûte ?
- Est-ce gratuit ?
- Vais-je être obligé de signer ?
- Qui va m'appeler ?
- Est-ce fiable ?
- Combien de temps ça prend ?
- Les entrepreneurs sont-ils vérifiés ?
- Est-ce disponible dans ma ville ?
- Est-ce que je peux avoir une subvention ?
- Pourquoi utiliser ce site plutôt que contacter quelqu'un directement ?

# Design Senior — UX/UI

Le design doit servir la confiance, la compréhension et la conversion.

## Direction créative

Par défaut :

- premium;
- moderne;
- grande marque;
- très peu de bruit visuel;
- typographie forte;
- espaces généreux;
- contraste clair;
- sections alternées blanc / gris très clair;
- cartes avec border et ombre légère;
- icônes SVG propres;
- coins arrondis premium;
- gradients subtils;
- aucune surcharge.

## Hiérarchie

Chaque écran doit avoir un point focal évident.

Ordre visuel :

1. H1;
2. bénéfice;
3. formulaire / CTA;
4. preuve;
5. contenu.

## Formulaire

Le formulaire doit paraître simple même lorsqu'il qualifie plusieurs critères.

Privilégier :

- champs regroupés;
- grandes zones cliquables;
- boutons / cards de sélection;
- multi-étapes si cela réduit la perception d'effort;
- progression visible;
- erreurs claires;
- maintien des données en cas d'échec;
- CTA très explicite.

## Mobile

Le mobile est prioritaire.

Vérifier :

- H1 non coupé;
- texte ≥ taille lisible;
- champs ≥ 44-48 px;
- aucun scroll horizontal;
- boutons larges;
- formulaire facile au pouce;
- CTA sticky si utile;
- header léger;
- chargement rapide.

# Formulaire et tracking

Formulaire par défaut :

- envoi vers `/api/lead`;
- traitement côté Cloudflare;
- transfert vers n8n;
- webhook jamais exposé côté navigateur;
- honeypot anti-spam;
- validation client + serveur;
- UTM conservés;
- `gclid` conservé;
- `fbclid` conservé;
- URL de landing enregistrée;
- timestamp;
- message d'erreur sans effacer les réponses;
- redirection vers `/merci.html` seulement après succès serveur.

Champs envoyés au minimum :

- source;
- page;
- landing_url;
- name;
- phone;
- email;
- city;
- service/project;
- réponses de qualification;
- utm_source;
- utm_medium;
- utm_campaign;
- utm_term;
- utm_content;
- gclid;
- fbclid;
- submitted_at.

# Cloudflare + GitHub + n8n

Architecture par défaut :

**GitHub** → code source

**Cloudflare Pages / Workers** → hébergement + CDN + Function serveur

**n8n** → automatisation

**GoHighLevel / CRM / Supabase / Google Sheets** → traitement du lead selon le projet

Règles :

- jamais de secret dans GitHub;
- secret `N8N_WEBHOOK_URL` côté Cloudflare;
- branche `main` = production lorsqu'elle est configurée ainsi;
- commits clairs;
- vérifier les fichiers avant modification;
- ne jamais casser un formulaire fonctionnel.

# Search Console — boucle d'amélioration

Quand Google Search Console est accessible :

Analyser :

- impressions;
- clics;
- CTR;
- position moyenne;
- requêtes;
- pages;
- pays;
- appareils;
- indexation;
- erreurs;
- cannibalisation;
- requêtes en positions 4 à 15;
- pages ayant beaucoup d'impressions mais peu de clics.

## Quick wins prioritaires

1. Requête commerciale en position 4-10 → améliorer page + maillage + preuve + title.
2. Beaucoup d'impressions / CTR faible → retravailler title/meta et adéquation à l'intention.
3. Deux pages sur la même intention → résoudre la cannibalisation.
4. Page indexée mais sans impressions → revoir intention, contenu, architecture et liens.
5. Page qui ranke mais ne convertit pas → CRO.

3. analyser la SERP;
4. définir l'angle marketing;

13. vérifier vitesse;

16. publier;

19. suivre les résultats;
20. améliorer selon les données.

# Standard de qualité obligatoire

Avant de considérer une page terminée, se demander :

- Est-elle meilleure et plus utile que les pages actuellement en tête ?
- La personne comprend-elle immédiatement l'offre ?
- Ai-je une vraie raison de faire confiance ?
- Le contenu est-il spécifique et non générique ?
- Le design ressemble-t-il à une grande marque ?
- Le formulaire est-il simple ?
- Le SEO technique est-il propre ?
- La page possède-t-elle une vraie valeur locale ?
- Le CTA est-il clair ?
- La page est-elle excellente sur mobile ?
- Les affirmations commerciales sont-elles vraies ?

Si plusieurs réponses sont « non », la page n'est pas terminée.
